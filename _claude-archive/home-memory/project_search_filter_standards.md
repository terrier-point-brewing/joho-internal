App-wide search/filter/sort/categorization standardization. Motivated by divergence: Batch Log used dropdown filters + no search, Export Bay used free-text + chip filters, Production Inventory had filters but no search, Taproom Inventory blended recipe+partner into one search box.

**Standard (3 rules):** categorical filters preferred where values are bounded; lean toward enabling sort; free-text search is entity-scoped + field-coded (different entities → separate controls; only an entity's own identity fields may share one box). State syncs to the URL. Full spec: `docs/superpowers/specs/2026-07-09-search-filter-standards-design.md`. Standard doc section added to `docs/UI_STANDARD.md`.

**PR 0 foundation — MERGED (squash) via PR #139, 2026-07-09.** Zero behavior change. Built:
- `lib/table/applyControls.ts` — pure filter+sort engine (+ test)
- `lib/table/urlState.ts` — ControlsState↔URLSearchParams + countActiveControls (+ test)
- `app/components/ui/useTableControls.ts` — thin URL-synced hook (delegates to the pure fns)
- `app/components/ui/{SearchInput,FilterChips,FilterSelect,FilterBar,SortableTh}.tsx` — primitives
- `scripts/check-search-filter.mjs` + CI step — **warn-only** guard (flips to `--strict` blocking in PR 4)

**Key contracts:** `config.sort.default` is applied by `parseControlsState` (urlState), NOT applyControls/hook. Params: `q`/`q_<field>`, dimension-name filters, `sort=key`|`-key`. Multi-table pages pass a `prefix`. Consumers MUST give `useTableControls` a stable `config` (module-scope/useMemo).

**Foundation extensions added in PR 1 (additive):** `FilterSpec.matches?: (row, selected[]) => boolean` (for group-predicate filters that aren't single-value equality — Export Bay filters recipes by "has an allocation in channel X"; `accessor` is now optional when `matches` is given). `useTableControls.setSort(key, dir)` for explicit/segmented (non-column) sorts.

**IMPORTANT engine bugfix (c629a6c):** `applyControls` `coerce()` used `parseFloat`, which truncated ISO date strings to their YEAR (`parseFloat("2026-07-09")`=2026) → same-year dates sorted equal (Date sorts were no-ops) AND numeric-leading names (`"8 Ball"`) sorted as numbers. Fixed to whole-string `Number()` (empty→text guard): ISO dates now sort chronologically via `localeCompare` (ISO-8601 is lexicographically chronological), alpha names sort as text, pure-numeric strings still numeric. So **date-sort accessors can return the raw ISO string** — no need for `.getTime()`. Regression-safe (nothing relied on parseFloat leading-numeric).

**Patterns proven in PR 1 (reuse in PR 2–4):** grouped layouts (Ingredients by category, Packaging by type) keep grouping by building groups from the hook's filtered `rows`; category/type colors pass through `FilterChips` `options[].className` (raw-color exception); tables use `SortableTh` + `toggleSort`; non-table domain sorts (Export Bay) use `FilterChips`-as-segmented + `setSort`; predicate/group filters use `matches`. **Suspense:** any route newly calling `useTableControls`(→`useSearchParams`) needs a `<Suspense>` boundary — `/production/*` inherits it from `app/production/loading.tsx`; Taproom needed an explicit page wrap.

**Deferred follow-ups (non-blocking, from final review):** (a) `applyControls` throws if a `FilterSpec` has neither `matches` nor `accessor` (untriggered; type doesn't prevent it); (b) default sort is written to URL on first interaction (cosmetic). **PR 2 must prefix the Export sibling tabs** (Shipments/Export Invoices share `/production/export`) — Export Bay already prefixed `bay_`; inventory child tabs use `ing_`/`pkg_`/`adj_`.
